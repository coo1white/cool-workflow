# types-util

## Scope (one line)

This covers the shared contract shapes and the small util layer: the 25 type files under `src/types/`, the barrel `src/types.ts`, and `src/util/fingerprint.ts` (with its unit test `src/util/fingerprint.test.ts`). There is no `src/index.ts` in this codebase.

## Public surface

### 1. Util functions (the only runtime code in this subsystem)

`src/util/fingerprint.ts` is the one canonical content-fingerprint implementation. It is a pure function of its arguments. It never imports run state or high modules (`src/util/fingerprint.ts:1-4`).

| Export | Takes | Does | Gives back |
|---|---|---|---|
| `fingerprintStrings(values: string[])` | a list of strings | copies the list, sorts it with the JS default sort (UTF-16 code-unit order), makes `JSON.stringify` of the sorted list, takes sha256 of those bytes | the string `sha256:` + the first 32 hex chars of the digest (39 chars total) (`src/util/fingerprint.ts:6-10`) |
| `fingerprintRecords(records: Array<{ id; status?; updatedAt? }>)` | a list of records | maps each record to `` `${r.id}:${r.status || ""}` ``, sorts, then calls `fingerprintStrings` (which sorts again). NOTE: `updatedAt` is in the parameter type but is NOT used | same `sha256:<32 hex>` string (`src/util/fingerprint.ts:12-14`) |

Both are order-independent: the same values in a different order give the same fingerprint (`src/util/fingerprint.test.ts:13-17`).

Who reads these at runtime:
- `src/node-snapshot.ts:29,81,228` — `sourceFingerprint` and `outputFingerprint` of node snapshots and replays.
- `src/state-explosion/helpers.ts:9-11` — imports both and RE-EXPORTS them, so state-explosion callers get the one canonical copy.
- `src/state-explosion.ts:19-20,490,750,985,1059,1177` — all derived-index fingerprints; it also re-exports `fingerprintStrings` at `src/state-explosion.ts:1327`.

Spec-debt / trap: `src/run-registry.ts:149-153`, `src/observability.ts:75-79`, and `src/evidence-reasoning.ts:771-774` still keep their OWN private copies of the exact same algorithm. The header comment in `src/util/fingerprint.ts:2` says the util "replaces duplicated copies in observability.ts and run-registry.ts (v0.1.95)", but the private copies are still there. All copies produce the same bytes, so outputs match; a rebuild must keep the algorithm identical everywhere.

Related helpers one level out (`src/state-explosion/helpers.ts`, pure, used by the derived-index layer): `isProtectedStatus`, `dominantStatus`, `parentMap`, `stableLine`, `sortKeys`, `stripRunId`, `unique`, `byId`, `truncate` (80-char cut with `...`), `slug` (`src/state-explosion/helpers.ts:13-66`).

### 2. The barrel `src/types.ts`

`src/types.ts:5-29` re-exports, in this order: `./types/core`, `workflow-app`, `result`, `trust`, `state-node`, `pipeline`, `error-feedback`, `sandbox`, `execution-backend`, `boundary`, `drive`, `report-bundle`, `multi-agent`, `topology`, `blackboard`, `worker`, `candidate`, `evidence-reasoning`, `run`, `schedule`, `run-registry`, `reclamation`, `workbench`, `observability`, `collaboration`. That is all 25 files under `src/types/`. Every export in every type file is a `type` or `interface` — there are ZERO runtime values in `src/types/` ("Pure types — no runtime cost", `src/types.ts:3`). About 49 `src/` modules import from `"./types"`; only `src/validation.ts:19-21` and `src/orchestrator/collaboration-operations.ts:5` import a domain file directly (`./types/candidate`, `./types/state-node`, `./types/worker`, `../types/collaboration`), so both import paths must keep working.

## Exact outputs

The fingerprint string is the one byte-level output this subsystem produces:

```text
format:  sha256:<first 32 hex chars of sha256(JSON.stringify(sorted values))>
length:  39 chars ("sha256:" = 7 + 32 hex)
```

Worked examples (computed with the exact algorithm from `src/util/fingerprint.ts:6-14`):

```text
fingerprintStrings(["a","b"])                         = sha256:0473ef2dc0d324ab659d3580c1134e9d
fingerprintStrings([])                                 = sha256:4f53cda18c2baa0c0354bb5f9a3ecbe5
fingerprintRecords([{id:"b",status:"ok"},
                    {id:"a",status:"fail"}])           = sha256:f0dd656217111ba9ceb4a09791a2a21c
```

`fingerprintStrings(["b","a","c"]) === fingerprintStrings(["c","b","a"])` (order-free), and `["x"]` vs `["y"]` differ (`src/util/fingerprint.test.ts:13-23`).

Width warning: other modules make FULL 64-hex `sha256:` digests with the same prefix — `src/telemetry-attestation.ts:254`, `src/ledger.ts:107`, `src/contract-migration.ts:102`, `src/coordinator/util.ts:19`, `src/reclamation/hash.ts:19-22`, `src/execution-backend/util.ts:14`. Only the fingerprint family cuts to 32. A rebuild must not mix the two widths.

Every string-literal union listed in the Public surface section is exact-output data: those strings are persisted in `.cw/` files and printed in `--json` payloads by other subsystems. Do not re-word any of them.

## Invariants and error behavior

1. `fingerprintStrings` never changes its input: it sorts a COPY (`[...values].sort()`, `src/util/fingerprint.ts:8`). The sort is the JS default (string, UTF-16 code-unit order). The JSON form is `JSON.stringify` of a string array — so JS string escaping rules are part of the contract.
2. `fingerprintRecords` folds a missing `status` to the empty string (`r.status || ""`), and IGNORES `updatedAt` even though the parameter type has it (`src/util/fingerprint.ts:12-13`).
3. The fingerprint functions never throw on any string input and do no I/O.
4. Boundary welds fail CLOSED at compile time: a callable anywhere inside `ExecutionResultEnvelope`, `ResultEnvelope`, or `UsageRecord` breaks `npm run build` (`src/types/boundary.ts:23-27,60-66`). A union with one bad member collapses `IsOneWayData` to `boolean`, which also fails (`src/types/boundary.ts:45-47`). `unknown` passes as opaque data (`src/types/boundary.ts:33-34`).
5. `schemaVersion: 1` is a LITERAL type on ~92 persisted-record interfaces across `src/types/` (count via grep). A rebuild that widens it to `number` loses the compile-time pin.
6. Runtime shape guards: `src/validation.ts` re-checks parsed JSON against the type definitions for `CandidateRecord`/`CandidateScore`, `NodeSnapshot`/`NodeReplayRun`/`NodeSnapshotBody`, and `WorkerScope` before trusting it — `validate*()` throws on mismatch, `tryValidate*()` gives back null (`src/validation.ts:1-21`). So field names and enum values in those three type files are load-bearing at RUNTIME, not only at compile time.
7. Fail-closed vocabulary rules baked into the types: absent usage = `unreported` never 0 (`src/types/observability.ts:99-101`); zero-sample rates = `"n/a"` never 0%/100% (`src/types/observability.ts:127-129`); unexplained adoption = `"unexplained"` never a made-up reason (`src/types/evidence-reasoning.ts:24-26`); unclassified reclaim path = RETAINED (`src/types/reclamation.ts:10-13`); `"verified"` evidence confidence is never auto-set (`src/types/result.ts:80-83`).
8. Append-only rules as types: trust-audit events chain by `prevEventHash`/`eventHash` (`src/types/trust.ts:80-86`); telemetry records chain by `prevHash`/`recordHash` (`src/types/observability.ts:26-59`); tombstones chain by `prevTombstoneHash`/`tombstoneHash` (`src/types/reclamation.ts:95-117`); collaboration corrections use `supersedes`, never edits (`src/types/collaboration.ts:8-12`).

## Edge cases

- `fingerprintStrings([])` is defined: sha256 of the two bytes `[]` → `sha256:4f53cda18c2baa0c0354bb5f9a3ecbe5`.
- Records with the same `id:status` line are NOT de-duplicated before hashing — but `JSON.stringify` of the sorted list keeps duplicates, so two same records vs one same record give DIFFERENT fingerprints.
- `WorkerMultiAgentMetadata` is declared in `src/types/topology.ts:140-146`, not in `multi-agent.ts`. Import paths that guess the "natural" home break.
- `src/types.ts` and the direct-file imports coexist: `src/validation.ts:19-21` bypasses the barrel on purpose ("Dependency-light by construction", `src/validation.ts:16-17`). Both routes must resolve.
- `RunExport.artifacts` is a LEGACY v0.1.74 field kept only so old archives load (`src/types/run.ts:280-282`); the modern field is `files`.
- `TrustAuditEvent` rows written before v0.1.81 have no hash chain and must verify as `unchained`, not broken (`src/types/trust.ts:82-85`, `src/types/trust.ts:96-98`).
- `RunQueueEntry` and `RunRecord` from before v0.1.37/v0.1.39 load unchanged: all scheduling and reclamation fields are optional with safe defaults (`src/types/run-registry.ts:119-121,152`).
- `QuickstartResult.resumedFrom` / `.bundle` / `.remote` are ABSENT (JSON-omitted) on the default path so the default output stays byte-identical (`src/types/drive.ts:91-111`). Same pattern for `RunResumeResult.drive` (`src/types/run-registry.ts:336-339`).
- `MultiAgentPolicyOperation` uses TypeScript template-literal types (`` `candidate.${...}` ``); the runtime strings are e.g. `candidate.register`, `judge.verdict` (`src/types/multi-agent.ts:41-44`).

## Rebuild risks

1. Fingerprint algorithm drift. It must be exactly `sha256(JSON.stringify([...values].sort()))` cut to 32 hex with the `sha256:` prefix. Any change — different sort order (locale sort, byte sort of UTF-8), different JSON escaping, full 64-hex width, no copy before sort — changes every `sourceFingerprint` on disk and flips freshness checks to `stale` everywhere.
2. Mixing the two digest widths. Fingerprints are 32 hex; content digests (`ledger`, `telemetry-attestation`, `reclamation/hash`, `coordinator/util`, `contract-migration`, `execution-backend/util`) are 64 hex, same `sha256:` prefix. Unifying them "for cleanliness" breaks byte-level parity.
3. `fingerprintRecords` semantics: missing `status` → empty string after the `:`, and `updatedAt` is ignored. Using `updatedAt` (the parameter type invites it) changes fingerprints.
4. Re-wording any string-literal union member. Every enum value here is persisted state and JSON output (`"n/a"`, `"unreported"`, `"unexplained"`, `"unattributed"`, `"re-runnable-by-reconstruction"`, `"concurrency-ceiling"`, `stage-timeout`, ...). One changed word breaks state loading and every parity test.
5. Dropping the boundary welds or the barrel line. `tsc` cannot notice a DELETED weld; only the smoke's source-text check does (`test/one-way-boundary-smoke.js:91-104`). A rebuild must keep the exact strings `AssertTrue<IsOneWayData<ExecutionResultEnvelope>>`, `...<ResultEnvelope>`, `...<UsageRecord>` in `src/types/boundary.ts` and `export * from "./types/boundary"` in `src/types.ts`.
6. Making optional fields required (or the reverse). The back-compat contract is that old records load unchanged: pre-v0.1.32 runs have no `collaboration`, pre-v0.1.81 audit events have no hash chain, pre-v0.1.37 queue entries have no lease fields, old exports use `artifacts` not `files`. Absent must stay a first-class, meaningful state (absent usage = `unreported`).
7. Putting `WorkerMultiAgentMetadata` in `multi-agent.ts`, or `ReportBundleResult` out of its leaf file. The leaf placement of `report-bundle.ts` exists to avoid a `types -> core` import cycle (`src/types/report-bundle.ts:1-4`); `drive.ts` imports it with a plain (non-`type`) import (`src/types/drive.ts:10`).
8. "Fixing" the spec-debt during rebuild: the private fingerprint copies in `run-registry.ts` / `observability.ts` / `evidence-reasoning.ts`, the unwired `fingerprint.test.ts`, the parked `commitMessageTemplate`, and the stale `tokenBudget` comment are FACTS of the old system. Reproduce behavior first; clean up only with proof of byte-parity.
