| 2026-07-13 | An async acquire path for `withFileLock` (`withFileLockAsync`, `src/shell/fs-atomic.ts`) so a long-lived process — the MCP server, `src/mcp/server.ts` — does not freeze its event loop during a contended lock wait | Frozen surface: needs an intent. Parked, not rejected — serves no North Star track directly (internal robustness, not pipeline/recovery/manifest) and is a large, higher-risk refactor. The 2026-07-13 perf-audit backoff fix cut the TYPICAL freeze and the frequency of long ones, but the acquire is still synchronous (`Atomics.wait`), so under PERSISTENT contention the calling thread — and the MCP server's whole event loop, including SIGINT/SIGTERM dispatch (`drive.ts:876-893`) — can still block for up to ~6s. But it only pays off once the MCP hot paths (`saveCheckpoint`, `withRunStateLock`, trust-audit append, telemetry — all synchronous today, called deep inside the ~197 synchronous tool handlers) go async up their whole call chains: ~20 call sites, and a half-converted chain is exactly where a silent state-corruption or a deadlock would hide — the failure mode the audit flagged. Needs its own `SPEC/state-core.md` pass (the lock protocol is byte-compat pinned), a design, and phased PRs; do NOT bundle it into a mechanical perf fix. Re-entrancy between a sync `withFileLock` and an async `withFileLockAsync` on the SAME target also needs a defined rule (`HELD_LOCKS` is one per-process set today). In fleet operation, where many parallel sessions run together with shared workers, the sync event-loop becomes a product ceiling — the whole control plane's speed is limited by lock contention from one session. This makes the async path a playbook requirement, not just a robustness fix. |

| 2026-09-03 | A copied run folder writes back into the folder it was copied from: refuse a `cw report`/`cw` command whose run state points outside the current tree, or rewrite the run's own absolute paths on load, so a plain copy of `.cw/runs/<id>` is safe to keep as a spare | Parked, not scheduled — needs its own intent.
